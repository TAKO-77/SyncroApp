# Agent Instructions

# 01 Purpose
This file gives AI coding agents the context and rules for working
on this project. Follow these every session.

# 02 Before You Start
- Read docs/PRD.md to understand the product and goals.
- Read docs/DESIGN_SYSTEM.md before building any UI (respect dark/light modes).
- Read docs/ARCHITECTURE.md before creating files or adding tools.
- Check existing components before creating new ones.

# 03 General Rules
- Use TypeScript for all files.
- Reuse existing components wherever possible.
- Keep code modular. One component, one job.
- Don't create unnecessary files.
- Only build what's in the PRD. Ask before adding features.

# 04 AI Behavior & Privacy (Stealth Mode)
- Never author commit messages, branch names, PR titles, or code comments that mention AI tools (e.g., "Generated by AI", "Assisted by Gemini").
- Local AI instruction files must be ignored via local git configuration (.git/info/exclude). Never modify the .gitignore file to add these, and never commit them to the remote repository.

# 05 Version Control & Hygiene
- Use "Conventional Commits" for all commit messages, keeping a natural and professional tone.
- Always run `git status` before each commit to ensure compiled files (*.class, target/), IDE metadata (.idea/), OS files (.DS_Store), or local credentials (.env) are not included.

# 06 Code & Architecture Guidelines
- Use functional components and modern React hooks.
- Use clear, meaningful names for components and Supabase queries.
- Handle loading, error, and empty states.
- Ensure all layouts are responsive and work across Expo's target platforms (Mobile and PC).
- Apply clean code principles with Separation of Concerns, and opt for data immutability wherever applicable.
- Ensure strong unit test coverage for acceptance criteria and verify the Definition of Done (DoD) before marking tasks as complete.
- Use standard Maven commands for application build and testing, specifically `mvn clean verify` and `mvn test`.

# 07 Documentation Management
- Compile `.puml` files to `.svg` whenever diagrams are modified. Never commit a source diagram file without its updated, corresponding image file.
- Ensure 100% synchronization between the terminology used in the project glossary and the domain model.

# 08 Security
- Never expose API keys or secrets in code.
- Use environment variables (.env) for Supabase URL and Anon Key.
- Validate all user inputs before sending to the backend.

# 09 Useful Commands
npm install # Install dependencies
npx expo start # Start the Expo development server (Hot Reload)
eas build # Run cloud builds via EAS

# 10 When Unsure
- Check the docs folder first.
- Look at how existing code does it.
- Ask before making big changes.
